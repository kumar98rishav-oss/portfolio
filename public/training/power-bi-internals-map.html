    Four rules before anyone pastes anything

    Rule 1
    Training model only

    Model files carry server names, file paths and RLS logic. Never paste a client's model into a public AI tool.

    Rule 2
    Commit before any edit

    Every change can then be reviewed with git diff and undone.

    Rule 3
    AI output is a draft

    Every claim it makes gets checked against Desktop.

    Rule 4
    Paste back cleanly

    Tabs, straight quotes, UTF-8 without BOM. The â€” text in the sample is what a wrong encoding does.

    Three different kinds of automation

    1 · Files
    Editing TMDL and PBIR on disk

    An AI client with file access does this with no MCP server at all. It is Module 6, automated, and it stays under Git.

    2 · Live model
    The model open in Desktop or Fabric

    The Power BI Authoring MCP server works through the Analysis Services engine. Register it read-only for a first session.

    3 · Report
    Pages and visuals

    Separate report tooling and the PBIR files. The modeling server does not change visuals.

    Carry this into Session 2: a measure written to the live model in Desktop lands outside Desktop's project state and can surface as "Something's wrong with one or more fields". Changes belong in the files, under Git. That is why this session came first.
